# 米粒测试版：设计与节奏分析

> 全部数字来自 `analyze.py` / `sweep.py` / `tune.py` 的实际运行输出（`results/*.json|txt`），用修复后的 IdleFramework（贪心玩家按“回本时间”购买）。

## 1. 文件
| 文件 | 内容 |
|---|---|
| `米粒测试版.json` | 改版前游戏（由 `build_game.py` 生成） |
| `资源.csv 生产者.csv 升级.csv 转生层.csv 自动购买.csv 叠加组.csv` | 改版前各表，可在 `/input` 页逐表导入 |

**注意**：里程碑（synergy 节点）和稻魂加成（state_modifier 边）在 `/input` 的表格里没有对应表，只用 CSV 导入会丢失；请用“选择 JSON 文件”导入完整版本。

## 2. 游戏设计（改版前）
- 资源：米粒 `rice`（初始 10），稻魂 `soul`（转生货币）。
- 生产者（产量/秒，基础价格，成长率）：稻田 1/10/1.07、水车 6/120/1.10、碾坊 40/1500/1.12、粮仓 260/2.2万/1.14、米商 1800/35万/1.16。
- 升级（乘算组 `upgrades`）：各生产者 x2（100 / 1500 / 2万 / 30万 / 500万），丰收全体 x2（100万），大丰收全体 x3（5000万）。
- 里程碑：每个生产者每拥有 25 个，该生产者产量 x2（`synergy`，公式 `2 ** floor(owned_X/25) - 1`）。
- 转生：稻魂总数 = `floor(sqrt(累计米粒/1e7))`，本次获得 = 总数 − 已有；重置米粒、生产者、升级；每个稻魂让所有生产者基础产量 +10%（`state_modifier` 边）。
- 自动购买：首次转生后（`balance_soul >= 1`）每 10 秒自动买稻田，数量 max。

## 3. 节奏目标（写在模拟之前）
| # | 目标 |
|---|---|
| I1 | 首次购买 ≤ 10 秒 |
| I2 | 水车 ≤ 1 分，碾坊 ≤ 4 分，粮仓 ≤ 10 分，米商 ≤ 25 分（首次购买时间） |
| I3 | 前 30 分钟：任意两次购买间隔 ≤ 60 秒；“有意义目标”（新生产者、升级、里程碑）间隔 ≤ 120 秒 |
| I4 | 首次转生 45–60 分钟，收益 ≥ 5 稻魂；第二轮追上第一轮末产量 ≤ 第一轮时长的 50% |
| I5 | 第 30 分钟时任一生产者产量占比 ≤ 60% |
| I6 | 2 小时内没有永远不买的升级 |

玩家模型：贪心（回本时间 = 等待时间 + 价格/Δ产量，Δ由引擎实测，含里程碑和稻魂）；转生策略：本次收益 ≥ max(5, 当前稻魂) 时转生（“翻倍”规则）；`--policy rate` 是短视对照组。

## 4. 结果：改版前 vs 目标
| 目标 | 改版前实测 | 是否达标 |
|---|---|---|
| I1 | 0 秒（初始 10 米粒直接买稻田） | ✅ |
| I2 | 水车 1.0 / 碾坊 1.7 / 粮仓 3.3 / **米商 8.3** 分 | 全部提前，节奏过快，后期内容 8 分钟就解锁完 |
| I3 | 任意间隔最大 259.7 秒（p90 8.8 秒）；有意义目标间隔最大 401.4 秒 | ❌ |
| I4 | 首次转生 **22 分钟**（+5）；第二轮**始终没有**追上第一轮末产量 | ❌ |
| I5 | 第 10 分钟：米商 38%、粮仓 33%（22 分钟就转生，没有 30 分钟数据） | — |
| I6 | 4 小时内所有升级都买过 | ✅ |
| 内置检测 `run_full_analysis` | 废升级 0、进度墙 0、主导生产者 = 米商（4.55 倍） | |

其他发现：
- **自动购买 max 会“饿死”玩家**：转生后自动购买每 10 秒把米粒全花在稻田上。第二轮第 10 分钟稻田占 83%，产量（3.81e4）**低于第一轮同一时刻（5.66e4）**；前 30 分钟最长等待 435 秒。
- 4 小时内转生收益 5→5→10→21→43→84→174 呈指数增长（共 342 魂），后期失控。
- 短视转生策略（`before_ratepolicy`）：每 15–20 分钟转生一次，每次只得 1 魂，4 小时共 14 魂，累计米粒 2.2e9。翻倍规则：342 魂，3.0e12。**同一套数值，玩家策略不同，结论差两个数量级。**

## 5. 敏感性扫描（`results/sweep.json`，3 小时；除“强制首转”外，转生用短视策略）
| 变体 | 米商解锁(分) | 首次转生(分) | 3 小时累计米粒 | 要点 |
|---|---|---|---|---|
| 基线 | 8.3 | 12.0 | 1.1e9 | |
| 自动购买 bulk=1 | 8.3 | 12.0 | **2.4e10** | 第二轮有意义目标最大间隔 756→190 秒 |
| 转生除数 1e9 | 8.3 | 28.0 | 1.0e10 | |
| 转生除数 1e10 | 8.3 | 61.0 | 4.4e10 | |
| 后期价格 x3 | 12.3 | 16.0 | 8.5e8 | |
| 后期价格 x10 | 未解锁 | 16.0 | 6.8e8 | 粮仓 9.6 分 |
| 成长率 +0.02 | 9.9 | 14.0 | 5.1e8 | |
| 里程碑每 50 个 | 10.2 | 15.0 | 2.8e8 | |
| 强制首转 30 分 | 8.3 | 30（+12） | 5.4e9 | |
| 强制首转 60 分 | 8.3 | 60（+32） | **4.2e11** | 第二轮最大间隔 68 秒 |

结论：解锁节奏主要由后期生产者的**基础价格**决定（成长率只做微调）；首次转生时间由**转生除数**决定（收益 ∝ sqrt，除数 ×10 大约把达到同样收益的时间推后 1 档）；**自动购买的数量设置是第二轮体验的关键**。

## 6. 专家组讨论（摘要）
- **数学家**：收益是 `floor(sqrt(累计))`，按整数跳变，所以“收益/时长”的峰值一跳就过，短视策略注定每次只拿 1 魂。翻倍规则在 sqrt 公式下更接近最优，但也只是经验规则；要谈“最优转生时机”，需要对整条多轮轨迹做优化，现在的框架做不到。另外，累计米粒在转生时不清零，稻魂总量由**全部历史**决定，所以每轮需要的时间不会自然缩短，第二轮“追赶”目标在这个公式下很难达到。
- **放置策划**：最该先改的是 8 分钟就解锁完米商的问题，以及自动购买“抢钱”。前 30 分钟最长等待 60 秒（I3）对放置游戏偏严，我可以接受 120 秒，但 6–7 分钟的空窗一定要用升级填上。
- **RPG 策划（不同意）**：拿“任意购买间隔”当体验指标意义不大，贪心玩家每秒都在买稻田。真正的“目标”应该是新内容、里程碑、转生。我更看重**有意义目标间隔**和**转生后第一分钟的爽感**。另外数值变化太大：第一轮内产量增长 7 个数量级，后期稻魂一轮翻倍，RPG 玩家会觉得没有成长感，只剩指数膨胀。
- **分歧 1**：放置策划要把转生除数调到 1e8 以上以符合 45–60 分钟；数学家指出这会让 4 小时总进度大幅下降（改版后 40 魂 vs 342 魂），“首转时间”和“长期增速”是互相拉扯的，要看目标是留存还是长线。最终按目标 I4 执行。
- **分歧 2**：内置主导检测说“米商主导 4.55 倍”，而按实际产量占比，改版后第 30 分钟**稻田占 69%**（里程碑 + 1.07 低成长率叠加）。数学家认为内置检测（只买单一生产者、不含升级和里程碑）不能代表真实玩家；放置策划认为稻田后期强一点可以接受（AdCap 也是这样）；RPG 策划要求压低。暂未改动，列为待决。

## 9. IdleFramework 目前表达或分析不了的
1. **升级不能指定购买货币**：没法做“用稻魂买的永久升级”，转生商店无法表达。
2. 转生层的 `bonus_type` 不生效，加成只能用 `state_modifier` 边逐个生产者手写。
3. `achievement` / `unlock_gate` 不生效，里程碑只能用 synergy 公式模拟；synergy 不支持 `_all`。
4. 优化器**不会自己决定何时转生**，转生策略写在本目录的 `analyze.py` 里，结论对策略非常敏感（见第 4 节）。
5. `run_time`（本轮时长）变量永远是 0；没有“本轮累计”变量，转生公式只能基于全历史。
6. 自动购买的购买**不进入购买记录**（引擎不记录），稻田在第二轮之后的首购时间等数据缺失。
7. 内置主导检测只模拟“只买一种生产者”，和真实占比结论相反；内置进度墙检测本例两版都是 0，与实测 5–6 分钟空窗不符（判定规则是：间隔 > 模拟时长的 20% 且增长 < 1.5 倍）。
8. 没有离线收益、点击、随机事件、玩家注意力或在线时长模型；没有自动调参（目前都是人工调）。
