# 《挖到地心》数值平衡经验包

> **本文为参考经验，不是唯一标准；用于后续验收、开发测试时对照。**
>
> 内容取自《挖到地心》3 小时重平衡各轮（v1–v5）的交付目录、回归结果、数学组分析备忘、存档实测复核、导入校验记录，以及挖矿 ↔ IdleFramework 适配包说明。文中数字都能在这些材料里找到；找不到的不写，或标「待验证」。
> 本文只是文档。第 4 节是《挖到地心》的游戏规则和定版数值，**不是引擎标准**；框架代码里没有任何挖矿专属规则。

## 1. 概要

**项目类型**：卡通鼹鼠挖穿地心的增量挖矿（单趟下钻 + 科技树），无广告、无转生。

- 玩家一趟一趟往下挖：打格子、掉矿，油耗尽（按每次挖击消耗）一趟结束，回地面结算，再用多种矿买科技。
- 科技树四支：伤害 / 炸药、燃料 / 超载激光、地震、世界 / 工厂无人机。全科技共 **488 级**，买满后进入 P11 结局。
- 难度档 P1–P11：**只切换档位，不重置**（科技、钱包都保留）。没有转生（prestige / rebirth）。
- 每格掉落次数 = 层序号 + 1，越深收益越高；高档位格子血量和掉落都按 5^(档位−1) 放大（部分矿除外）。

**最终验收目标与结果**（**v5 定版 = 候选 A7**，Tony 确认；模拟已按真实存档校准单趟时长 / 产出；4 案 = v2 玩家 × 低 / 中 / 高结算时长 + v3 玩家 × 中结算时长）：

| 验收项 | 目标 | v5 结果 | 判定 |
| --- | --- | --- | --- |
| 无广告全科技 488 级 + P11 结局总时长 | 理想约 3 小时；可接受 2.0–3.8 小时；**绝不低于 2 小时** | 4 案 2.89–3.20 小时，主案 3.20 小时 | 过 |
| 首个科技 + 首个小卡点 | 5 分钟内 | 首个科技 0.48 分钟；首个功能门（收集者）2.4 分钟开始攒、等 3.39 分钟、5.8 分钟买下；前 5 分钟买了 9 级 | 过（v5 报告判过；买下时刻略过 5 分钟） |
| 已有功能的强化 | 约 1 趟收入内买得起 | 多趟强化等待 9 处，最长 4 趟（v4 同模型下 24 处 / 14 趟） | 基本过，记账 |
| 功能门逐个变难 | 等待时长严格递增 | 多趟功能门梯 3.4 → 4.7 → 5.3 → 11.3 → 15.1 → 12.4 → 10.4 → 6.3 分钟，尾部 3 个下降（最后一个是随机掉落的遗物宝箱） | 未完全达标，记账 |
| 诱惑节点（碎岩弹片） | 刚解锁时明显买不起 | 首次可解锁（80.6 分钟）时持有 石约 84 万 / 铱约 13 万，价格 石 6800 万 / 铱 680 万；149.6 分钟才买 | 过 |
| 钻石打磨 → 效率 III 依赖保留 | 保留 | 73.9 分钟买钻石打磨，76.5 分钟买效率 III（间隔 2.6 分钟） | 过 |

## 2. 通用方法（可迁移到其他放置 / 挖矿 / 增量项目）

### 2.1 玩家买法决定结果，先把买法定下来

- 同一套原始数值，只换玩家买法：
  - 旧的纯贪心（只为当前最优目标攒钱）：**26.99 小时**；
  - v2 玩家（为目标攒钱，同时顺手买掉买得起的便宜升级）：**4.71 小时**；
  - v3 玩家（按档位评估收益）：4.82 小时。
  （以上为校准前的旧模拟口径，只用来比较买法。）
- 纯贪心会制造**假墙**：玩家死攒一个大目标，别的便宜升级一概不买，看起来是"卡关"，其实是买法问题。数值调之前，先把买法换成 v2 这种"攒目标 + 顺手买便宜货"。
- 模拟里的买法是"仅模拟"，和游戏规则分开写；验收报告必须写清用的是哪种玩家。

### 2.2 锁定数值前，先用真实存档校准单趟时长和产出

**这是本项目最大的一次返工。**

- v4 定价时，模拟里的单趟时长和产出只来自内部假设，没有对过真实游戏。v4 主案算出 2.98 小时，6 案 2.57–3.39 小时，看起来全部过线。
- 2026-10-20 拿一份真实存档（P2 档）对照：
  - 旧模拟：P2 直潜一趟 21.6 秒、石 1095、银 127（石:银 8.6:1）；
  - 实测：一趟约 50 秒、石 988、石:银 14:1；
  - 折算下来每秒收入只有旧模型的约 0.45 倍，银只有约 0.24 倍。
- 按实测校准后（时长系数 1.318、产出系数 0.50、银再 ×0.844），同一套 v4 数值：
  - 直潜校准模型 6 案 6.68–8.26 小时（主案 6.68）；横挖 + 停留层模型主案 8.15 小时；
  - 首个功能门从约 5 分钟推迟到 13–15 分钟；
  - 都远超 3.8 小时上限。v4 作废，在校准后的模型上重做 v5。
- 教训：
  - **只按内部假设校准的模拟，总时长可以差 2 倍以上**，而且 6 案稳健性检查查不出这种系统偏差（所有案一起偏）。
  - 锁定数值之前，至少拿 1–2 份真实存档（最好不同档位）对照单趟时长、各矿产出和矿种比例；v5 用了 P1、P2 两个点，产出系数分别 0.513 / 0.488，彼此一致才取 0.50。
  - 先排除环境问题，再查模型：复核时一度怀疑是噪声库缺失造成偏差，查下来旧估算用的就是真实噪声，真正的偏差在单趟时长 / 产出。
  - 校准系数、校准用的存档、日期都写进交付表。

### 2.3 用真实刷出率，不用表上的权重

- 配置表里每层矿的权重不等于玩家实际拿到的比例：实际出矿受噪声生成影响。
  - 砾石层金：表上 7% → 实际约 **0.8%**；
  - 泥土层银：表上 17% → 实际约 **5.8%**。
- 按表权重算，早期金、银收入会被大幅高估，所有用金银定价的门都会变成长墙。
- 工具环境也要核对：曾有一次脚本用了缺噪声库的环境，静默退回均匀分布，泥土层银变成 26.5% / 金 0.9%（真实噪声：银 15.4% / 金 0%）。**跑数前断言噪声库已加载。**

### 2.4 完整模拟是混沌的，验收看多案

- 一处小改价会改变后面整条购买路径。单跑主案容易"刚好过线"。
- 每个候选都要跑多案：v2 / v3 两种玩家 × 低 / 中 / 高三档每趟结算时长（v1–v4 每轮 6 案；v5 定版跑了 4 案，见 4.4）。全部在可接受区间内才算候选通过。
- 实例：
  - 第一轮主案 2.95 小时，但 v2 高结算时长 4.74 小时，超线；
  - 第二轮把一个功能门改便宜后，部分案在 P2–P4 就碰到用金 / 铱定价的门，总时长变成 5–10 小时，全部淘汰；
  - 第五轮候选 A4（不修燃料加满！！！）主案 3.32 小时，但 v3 玩家 5.08 小时、低结算 4.54 小时（P5→P6 卡关）；补上该修复后的 A7 才全部过线。
- 结论性发现：高结算与中结算案之间的收入比约 ×2–3，**不存在一个单一价格能让各案的某道门等待同时落在目标带内**。要么以主案为准，要么分案设目标，需要产品拍板。
- 多案稳健性只能发现"买法 / 结算时长"带来的偏差，发现不了模型本身的系统偏差（见 2.2）。

### 2.5 卡点多半是资源争用或成本悬崖

- 第二轮的 16–28 分钟卡点不是飞旋镐太贵，而是它要石头 + 铱，玩家为它攒钱时就不买石头系的力量升级，而力量升级正是开下一档的前提，于是在 P2 一直刷。
- 解法不是直接降价，而是**把价格大部分挪到那个时段正闲着的矿上**（飞旋镐挪到工厂矿；回旋镐挪到金）。玩家攒它时，紧张的矿还能继续买力量升级。
- 第五轮的另一种卡点：P5 → P6 要靠燃料加满！！！ 之后的深潜才能解锁，贪心玩家不买它时卡约 2 小时（成本悬崖）。单独把它的价格压到 ×0.2 后消除。
- 改价前先看：这个时段哪种矿在堆积、哪种矿紧张；目标门别和推进主线抢同一种矿；开档依赖的节点不要太贵。
- 单纯降价的副作用：门消失（等待≈0，不再是门），或者门序前移、暴露后面更贵的门。

### 2.6 整体缩放 + 定点修正

- v5 的做法：在 v4 结构上，所有可挖矿的成本数量统一 ×0.45（增长不动），早期银价（≤500）再 ×0.6，少数节点单独定系数，诱惑节点单独 ×4。
- 系数先扫一遍：×0.35 / 0.40 / 0.45 / 0.50 / 0.55 主案分别约 2.93 / 2.98 / 3.23–3.32 / 3.38 / 6.08 小时；×0.55 时 P5 卡 2.1 小时。（各候选的定点修正不完全相同，只能看趋势。）整体系数附近也有悬崖，要扫，不要只试一个点。
- 只改层权重、层血量而不缩放成本（B 组）时 >4.6 小时，卡在银上；结构没问题时，整体缩放比逐个调更稳。

### 2.7 强化增长要封顶

- 规则：已经解锁的功能，后续等级要在约 1 趟收入内买得起。
- 原表里强化的每级增长 0.6–1.1，后几级会变成墙。统一把强化增长**封顶 0.5**（结构性规则，不逐个调，v5 沿用）。
- 效果：v4 旧模型下强化最长等待从原表 49.3 分钟降到 5.1 分钟；v5 校准模型下多趟强化等待 9 处、最长 4 趟。

### 2.8 门的节奏：用目标曲线或单调性检查，不只看总时长

- 只看总时长会漏掉"中间一道 20 分钟尖刺、旁边几道几乎不等"的情况。
- 数学组从第三轮的功能门等待拟合了一条目标曲线：**等待 ≈ 2.53 × t^0.20 分钟**（t 为该门的时刻，分钟），目标带 ×0.7–1.3。v4 用它检查过（15 道门 9 道偏离 ±30%）。
- v5 用的是单调性检查：只看要攒 2 趟以上的功能门，后一道比前一道短 20% 以上记一次违例。
- 随机掉落（如遗物宝箱）单独标出，不和确定性门一起判单调。

### 2.9 诱惑节点和绕路

- 诱惑节点：刚解锁时明显买不起、需要很多趟收入的节点，让玩家先绕开、以后再回来。它只应挡住自己的几级后续，不挡主线。
- 整体降价时诱惑节点要单独反向调（v5 中碎岩弹片 ×4，抵消整体 ×0.45），否则会变成"顺手买"。
- 玩家只有在另一条路也是大障碍时才会绕路；所以不要指望"把一条路弄贵"就能改玩家路线，主线依赖要保留（例：钻石打磨 → 效率 III 这条依赖保留）。

### 2.10 工程纪律

- **确定性**：模拟里有一处遍历顺序不确定，修复（排序后遍历）后基线从 4.71 小时变成 4.60 小时。比较候选前先保证同输入逐位复现。
- **模型修正要单独记**：v5 模型还修了两处：技能冷却按整数击数触发；横挖单趟设 240 模型秒上限（否则回油大于耗油时会出 3600 秒的假趟）。加缓存提速后结果逐位一致。
- **导入后再跑一遍**：改价补丁写进真实配置文件后，用改好的配置（不加任何覆盖层）重跑主案，必须和"原配置 + 补丁覆盖"的结果逐位一致；同时做文本差异检查，确认只改了预期的行。
- 每轮交付都带：改动表（旧值 / 新值 / 原因）、功能门梯、分档用时、多案结果表、校准参数。

### 2.11 交付

- 给人看的表用中文名和数字，程序名放附录（见 4.5）。
- 游戏规则（本项目的设计约束）和引擎能力分开写：引擎只提供多货币价格、前置解锁、多目标加成、估值权重等通用能力；"3 小时""5 分钟""诱惑节点"这些是本项目规则。

## 3. 以前不擅长的机制：思路（待验证方向，不是结论）

| 机制 | 建议怎么看 |
| --- | --- |
| 非几何价格（每级在上一级上向下取整累加） | 小底价、慢增长时，几何公式会偏低 50%–75% 以上。先按真实公式逐级展开成固定价，再进框架分析。 |
| 一级要多种矿 | 每种矿单独看"攒够要几趟"，取最慢那种当瓶颈；改价时优先动瓶颈矿以外的分量。 |
| 单趟结算（不是每秒产出） | 时间单位取"趟"更稳；按秒折算会把"挖得更深但更久"的升级误判为负收益。单趟时长本身必须对真实存档校准（2.2）。 |
| 不重置的难度档 | 换档等于换一套每趟产出，不要用转生重置去建模。 |
| 随机掉落的宝箱 / 遗物 | 门梯里单独标出，不和确定性门一起判单调。 |

## 4. 挖到地心专属附录（游戏规则，不是引擎标准）

| 规则 | 内容 |

## 5. 验收清单（下个项目可直接照做）

**校准（锁定数值之前）**
- [ ] 至少 1–2 份真实存档（不同档位）对照单趟时长、各矿产出、矿种比例；记下校准系数和存档日期。
- [ ] 不同存档点的校准系数彼此一致；不一致先查模型，不要硬取平均。
- [ ] 换了模型或校准后，旧候选全部在新模型上重跑，不沿用旧结论。

**买法与口径**
- [ ] 玩家买法是显式参数，至少两种（如 v2、v3）；报告写明用的哪种。
- [ ] 先用新买法重跑原数值，作为基线；不用纯贪心的结果下结论。
- [ ] 出矿 / 掉落按真实生成（噪声）统计，不用表上权重；跑数前断言依赖库已加载。
- [ ] 同输入逐位复现；修过不确定性后重跑基线。

**总时长与稳健性**
- [ ] 2 种玩家 × 低 / 中 / 高结算时长共 6 案全部在可接受区间内，且不低于下限；少跑的案写进挂账。

- [ ] 整体缩放系数要扫一组值，确认附近没有悬崖。
