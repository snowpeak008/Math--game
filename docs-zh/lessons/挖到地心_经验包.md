# 《挖到地心》数值平衡经验包

> **本文为参考经验，不是唯一标准；用于后续验收、开发测试时对照。**
>
> 内容取自《挖到地心》3 小时重平衡各轮（v1–v4）的交付目录、回归结果、数学组分析备忘、导入校验记录，以及挖矿 ↔ IdleFramework 适配包说明。文中数字都能在这些材料里找到；找不到的不写，或标「待验证」。
> 本文只是文档。第 4 节是《挖到地心》的游戏规则和定版数值，**不是引擎标准**；框架代码里没有任何挖矿专属规则。

## 1. 概要

**项目类型**：卡通鼹鼠挖穿地心的增量挖矿（单趟下钻 + 科技树），无广告、无转生。

- 玩家一趟一趟往下挖：打格子、掉矿，油耗尽（按每次挖击消耗）一趟结束，回地面结算，再用多种矿买科技。
- 科技树四支：伤害 / 炸药、燃料 / 超载激光、地震、世界 / 工厂无人机。全科技共 **488 级**，买满后进入 P11 结局。
- 难度档 P1–P11：**只切换档位，不重置**（科技、钱包都保留）。没有转生（prestige / rebirth）。
- 每格掉落次数 = 层序号 + 1，越深收益越高；高档位格子血量和掉落都按 5^(档位−1) 放大（部分矿除外）。

**最终验收目标与结果**（v4 定版 = 第三轮候选 E + J4 改价；据 Tony 记录 2026-10-21 定稿；6 案 = 两种玩家 × 低 / 中 / 高结算时长）：

| 验收项 | 目标 | v4 结果 | 判定 |
| --- | --- | --- | --- |
| 无广告全科技 488 级 + P11 结局总时长 | 理想约 3 小时；可接受 2.0–3.8 小时；**绝不低于 2 小时** | 6 案 2.57–3.39 小时，主案 2.98 小时 | 过 |
| 首个科技 + 首个小卡点 | 5 分钟内 | 首个科技 0.4 分钟；首个功能门（收集者）1.59 分钟开始攒、等 3.4 分钟、4.99 分钟买下 | 过 |
| 已有功能的强化 | 约 1 趟收入内买得起 | 强化最长等待 49.3 → 5.1 分钟、最长 44 → 5 趟；但仍有 18 处强化等待超过 1 趟 | 基本过，记账 |
| 功能门逐个变难 | 等待时长严格递增 | 15 道功能门中 9 道偏离目标曲线超过 ±30%（7 道偏低、2 道偏高），不单调 | **未过，Tony 接受** |
| 诱惑节点（碎岩弹片） | 刚解锁时明显买不起 | 解锁时持有 石约 328 万 / 铱约 41 万，价格 石 3800 万 / 铱 380 万；约 47 分钟后才买 | 过 |

## 2. 通用方法（可迁移到其他放置 / 挖矿 / 增量项目）

### 2.1 玩家买法决定结果，先把买法定下来

- 同一套原始数值，只换玩家买法：
  - 旧的纯贪心（只为当前最优目标攒钱）：**26.99 小时**；
  - v2 玩家（为目标攒钱，同时顺手买掉买得起的便宜升级）：**4.71 小时**；
  - v3 玩家（按档位评估收益）：4.82 小时。
- 纯贪心会制造**假墙**：玩家死攒一个大目标，别的便宜升级一概不买，看起来是"卡关"，其实是买法问题。数值调之前，先把买法换成 v2 这种"攒目标 + 顺手买便宜货"。
- 模拟里的买法是"仅模拟"，和游戏规则分开写；验收报告必须写清用的是哪种玩家。

### 2.2 用真实刷出率，不用表上的权重

- 配置表里每层矿的权重不等于玩家实际拿到的比例：实际出矿受噪声生成影响。
  - 砾石层金：表上 7% → 实际约 **0.8%**；
  - 泥土层银：表上 17% → 实际约 **5.8%**。
- 按表权重算，早期金、银收入会被大幅高估，所有用金银定价的门都会变成长墙。
- 工具环境也要核对：曾有一次脚本用了缺噪声库的环境，静默退回均匀分布，泥土层银变成 26.5% / 金 0.9%（真实噪声：银 15.4% / 金 0%）。**跑数前断言噪声库已加载。**

### 2.3 完整模拟是混沌的，验收看 6 案

- 一处小改价会改变后面整条购买路径。单跑主案容易"刚好过线"。
- 每个候选至少跑 6 案：v2 / v3 两种玩家 × 低 / 中 / 高三档每趟结算时长。6 案都在可接受区间内才算候选通过。
- 实例：
  - 第一轮主案 2.95 小时，但 v2 高结算时长 4.74 小时，超线；
  - 第二轮把一个功能门改便宜后，部分案在 P2–P4 就碰到用金 / 铱定价的门，总时长变成 5–10 小时，全部淘汰；
  - 第二轮备选方案在收集者约 5 分钟上达标，但每案在 P2 都出现 16–28 分钟的飞旋镐死攒，v3 高结算 3.85 小时，淘汰。
- 结论性发现：高结算与中结算案之间的收入比约 ×2–3，**不存在一个单一价格能让 6 案的某道门等待同时落在目标带内**。要么以主案为准，要么分案设目标，需要产品拍板。

### 2.4 卡点多半是资源争用：把价格挪到闲置矿上

- 第二轮的 16–28 分钟卡点不是飞旋镐太贵，而是它要石头 + 铱，玩家为它攒钱时就不买石头系的力量升级，而力量升级正是开下一档的前提，于是在 P2 一直刷。
- 解法不是直接降价，而是**把价格大部分挪到那个时段正闲着的矿上**（飞旋镐挪到工厂矿；回旋镐挪到金）。玩家攒它时，紧张的矿还能继续买力量升级。
- 改价前先看：这个时段哪种矿在堆积、哪种矿紧张；目标门别和推进主线抢同一种矿。
- 单纯降价的副作用：门消失（等待≈0，不再是门），或者门序前移、暴露后面更贵的门。

### 2.5 强化增长要封顶

- 规则：已经解锁的功能，后续等级要在约 1 趟收入内买得起。
- 原表里强化的每级增长 0.6–1.1，后几级会变成墙。统一把强化增长**封顶 0.5**（结构性规则，不逐个调）。
- 效果（v4 vs 原表）：强化最长等待 49.3 → 5.1 分钟，最长 44 → 5 趟。

### 2.6 门的节奏：用目标曲线检查，不只看总时长

- 只看总时长会漏掉"中间一道 20 分钟尖刺、旁边几道几乎不等"的情况。
- 数学组从定版前的功能门等待拟合了一条目标曲线：**等待 ≈ 2.53 × t^0.20 分钟**（t 为该门的时刻，分钟；数学组拟合时用购入时刻，v4 门梯用开始攒钱的时刻），目标带 ×0.7–1.3。
- 每道功能门标"偏低 / 合格 / 偏高"。偏低太多说明门不成门；偏高说明是尖刺。
- 设计意图是"逐个变难"，但实际要和总时长、6 案稳健性一起取舍；v4 在这一项上没达标，经 Tony 判断后接受。

### 2.7 诱惑节点和绕路

- 诱惑节点：刚解锁时明显买不起、需要很多趟收入的节点，让玩家先绕开、以后再回来。它只应挡住自己的几级后续，不挡主线。
- 玩家只有在另一条路也是大障碍时才会绕路；所以不要指望"把一条路弄贵"就能改玩家路线，主线依赖要保留（例：钻石打磨 → 效率 III 这条依赖保留）。

### 2.8 工程纪律

- **确定性**：模拟里有一处遍历顺序不确定，修复（排序后遍历）后基线从 4.71 小时变成 4.60 小时。比较候选前先保证同输入逐位复现。
- **导入后再跑一遍**：改价补丁写进真实配置文件后，用改好的配置（不加任何覆盖层）重跑主案，必须和"原配置 + 补丁覆盖"的结果逐位一致；同时做文本差异检查，确认只改了预期的行。
- 每轮交付都带：改动表（旧值 / 新值 / 原因 / 实测首次购买时间 / 实测最长等待）、功能门梯、卡点梯、分档用时、6 案稳健性表、前 5 分钟时间线。
- 原因要按定版值重写，并附实测列，方便有人拿模拟逐条核对。

### 2.9 交付

- 给人看的表用中文名和数字，程序名放附录（见 4.5）。
- 游戏规则（本项目的设计约束）和引擎能力分开写：引擎只提供多货币价格、前置解锁、多目标加成、估值权重等通用能力；"3 小时""5 分钟""诱惑节点"这些是本项目规则。
- 未达标但接受的项目，写清楚数字和由谁拍板。

## 3. 以前不擅长的机制：思路（待验证方向，不是结论）

| 机制 | 建议怎么看 |
| --- | --- |
| 非几何价格（每级在上一级上向下取整累加） | 小底价、慢增长时，几何公式会偏低 50%–75% 以上。先按真实公式逐级展开成固定价，再进框架分析。 |
| 一级要多种矿 | 每种矿单独看"攒够要几趟"，取最慢那种当瓶颈；改价时优先动瓶颈矿以外的分量。 |
| 单趟结算（不是每秒产出） | 时间单位取"趟"更稳；按秒折算会把"挖得更深但更久"的升级误判为负收益。 |
| 不重置的难度档 | 换档等于换一套每趟产出，不要用转生重置去建模。 |
| 随机掉落的宝箱 / 遗物 | 门梯里单独标出，不和确定性门一起判单调。 |
