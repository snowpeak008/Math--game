# 中文数值录入界面 设计方案

## 1. 目标与用户
- 用户：已有游戏内容（Excel/配置表）的数值策划。
- 目标：**不画节点图、不手写 JSON**，按“系统”填表或粘贴已有表格 → 立刻看到错误 → 一键模拟。
- 原则：在现有前端（React 19 + Vite + Tailwind v4 + React Router，`frontend/`）上**新增一个页面**，不重写原有 Play/Analyze/Editor；后端只做最小补充。

## 2. 信息架构
```
顶栏：游戏名 | 载入已有游戏 | 新建空白 | 导出 JSON | 错误/提醒计数
系统标签页：资源/货币 | 生产者 | 升级/倍率 | 转生层 | 自动购买 | 叠加组   （每个标签显示行数与错误数）
  └ 可编辑表格（必填*、单元格错误标红、提醒标黄、悬停显示原因）
  └ 从表格导入：粘贴（Excel 复制=TSV）/ CSV / JSON 文件；替换或追加；表头中英文别名识别
  └ 导出本表 CSV（带 BOM，Excel 打开不乱码）
校验结果：本地检查（行号定位，可点击跳转）+ 服务器检查（与 Python 引擎同一套 pydantic 规则）+ “引擎不生效节点”警告
模拟：时长 → 保存并模拟 → 产量/购买次数/模拟到几秒/主导生产者/废升级/进度墙/各项首次购买时间
```

## 3. 数据映射（`frontend/src/input/schema.ts`）
- 每张表 = 一种节点类型，列定义 `SYSTEMS[]`（key、中文名、类型、必填、别名、提示）。
- `buildGame()`：表格 → `GameDefinition`。生产者表的“产出资源”列自动生成 `production_target` 边；升级引用但未定义的叠加组自动按乘算补齐。
- `gameToTables()`：JSON → 表格；表格不覆盖的节点/边（buff、synergy、achievement、state_modifier…）放到 `extra` 里**原样保留**，保存/导出时合并回去，不丢数据。
- 草稿自动保存在浏览器 localStorage。

## 4. 校验分两层
1. 前端即时（`checkTables`）：必填、数字格式、枚举值、ID 规则/重复、引用存在（产出资源、升级目标、重置/保留项、自动购买目标、转生货币），以及设计提醒（成长率 ≤1、≥1.3）。
2. 服务端（新增 `POST /api/v1/games/validate`，`server/routes/games.py`）：完整 pydantic 校验 + 公式编译 + 对引擎不生效的节点类型给警告。不保存。

## 6. 下一步（按优先级）
1. **对接用户真实表格格式**：按他们的 Excel 列名加别名或做“列映射”弹窗；支持 .xlsx 直接读取（引入 SheetJS，需确认依赖许可/版本）。
2. **一行多级数据**：很多项目是“等级表”（第 1~200 级逐级价格/产量），需要“等级表 → 拟合成 base×growth^n 或分段”导入器，或者引擎支持查表定价。
3. **引擎扩展**（录入才有意义）：购买货币字段（多货币）、unlock_gate/achievement 生效、转生时机策略、去掉 500 步静默截断、修时间线 bug。
4. **目标与调参**：在界面上填“节奏目标”（第 N 个生产者 X 分钟、首次转生 Y 小时），后端做参数搜索，给出建议数值——这是“平衡”而非“分析”的关键一步。
5. 结果可视化：产量曲线、购买间隔曲线（复用已有 plotly）。
6. 导出给 Unity：JSON/CSV 回写到游戏配置格式。
