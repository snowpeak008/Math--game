# 优化器说明（v0.1.6）

## 1. 引擎自动购买与优化器隔离
`PiecewiseEngine.advance_to()` 自带一套购买策略（挑下一个能买的东西、免费购买）。v0.1.5 之前，beam / BnB / MCTS 在等待时调用 `advance_to`，引擎会顺手替它们买东西，而且这些购买不进入优化器的购买记录。所以旧版本里这三个优化器的结果，很大程度上其实是引擎自身策略的结果。

v0.1.5 起的规则如下。

- **引擎开关**：`engine.auto_purchase` 控制内置策略和免费购买，`engine.game_autobuyers` 控制游戏里的自动购买器节点。
- **优化器默认行为**：beam / BnB / MCTS 运行期间默认 `auto_purchase=False`（构造参数 `engine_autobuy=True` 可恢复旧行为），运行结束后恢复原值。购买记录和最终状态一一对应。
- **预留账本**：
  - 优化器锁定一个目标后，调用 `engine.reserve_for(id)` 按币种预留所需数额。游戏自动购买器只能花「余额 − 预留」的部分。
  - beam / BnB / MCTS 默认启用预留。
  - greedy 默认不启用（`reserve_targets=False`）：一旦启用，greedy 在攒钱期间自动购买器会一直被饿死，与真实游戏不符。

## 2. beam 排序（v0.1.6）
默认 `rank="rollout"`：每个分支用 greedy 补全到 T，以补全后的最终产出打分；返回见过的最好完整方案。根节点的补全就是 greedy 轨迹，所以结果永远 ≥ greedy。

v0.1.5 的 `sync` 排序有缺陷，因此当时出现「宽度越大越差」：
- 它保留时间上最落后的分支；
- 已经推进到 T 的分支排在最后，被挤出 beam；
- 最终取 beam[0]，也就是最落后的分支，而不是最终产出最高的分支。

代价约为 O(branch_steps·w²) 次 greedy 补全，默认 `branch_steps=32`。beam 搜索本身不保证宽度单调，实测结果见 PROGRESS_fix3。API 默认 beam_width 为 5，上限 32。

## 3. BnB 上界
- **旧上界不成立**：旧上界「当前产出 + 剩余步数 × 当前候选最大 Δ」不是真正的乐观上界。升级会放大之后的 Δ；生产其它货币的节点主货币 Δ 为 0，却能解锁商店物品。实测：深度 4 时旧上界给出 242，穷举最优是 360。
- **新上界**（`bound="sound"`）：假设全部升级都已购买，取此时的主货币产出 P_all，再加「剩余步数 × 单个生成器在全升级状态下的最大边际产出」。
- **成立前提**（`sound_bound_applicable`）：节点只有资源 / 生成器 / 升级；边只有 production_target；没有余额联动；升级都不减益；引擎自动购买关闭。
- **默认 `bound="auto"`**：满足前提时用新上界，否则不剪枝（即穷举）。`bound="legacy"` 保留旧上界，仅供对照。
- **代价**：新上界很松，目前的实验里一次剪枝都没有发生。

## 4. MCTS（实验性，不推荐使用）
已冻结，不再列入对比表。推测 rollout 只买 5 件就闲置到 T，导致不同时间点的状态被直接比较；该问题尚未修复。

可负担过滤时，多货币候选的等待时间改为在实时引擎上重新计算。

## 5. 机会成本（实验项，默认关闭）
greedy 设 `oc_mode="derivative"` 时，λ = d(收入)/d(存量) 从游戏结构推出，不需要调参。

- **净增益**：购买的净增益 = Δ产出 −［I(B) − I(B − c)］，其中 B = max(余额, c)。线性存量联动时恰好等于 k·c，没有存量联动时为 0。
- **假设**：这部分收入损失被当作永久损失，而存量实际会回涨，所以高估了损失。在 stock_log 上这会导致严重少买。
- **对照基线**：`save_floor=X`（「攒到 X 再买」），用于网格搜索。

## 6. 余额联动溢出（v0.1.6）
线性余额联动的增长率与余额成正比（dx/dt = a + kx），余额会指数（或更快）增长。
- **不会静默变成 inf**：超出 float 范围时抛出 `StockOverflowError`，附带对数空间的 ln x 和对应的 BigFloat。
- **闭式解**：ln x = kt + ln(x0 + a/k) + log1p(…)，计算过程中不生成 e^{kt}。
- **静态检查**：会给出「无界指数增长机制」警告。

## 7. 关卡掉落节点 FarmNode（串行模型）
- **刷图方式**：一次只刷一个关卡，选当前战力 ≥ 门槛的最高关卡。之后会改用战斗关卡的胜率来判断能否稳定通关。
- **掉落速率**：掉落/次 × 通关次数/秒，通关次数 = min(1/通关耗时, 体力回复/每次体力消耗)。这里按稳态计算，不模拟体力存量缓冲。
- **事件**：战力跨过某关门槛时切分时间段。
- **死锁判定**：只有当某货币在依赖图里完全没有可达来源（没有生产者、没有掉落、没有转换路径）时，才报死锁。

## 8. 约束货币
候选里的 `binding_currency` / `binding_kind` 取所有成本和 requires 门槛中等待最久的那一项；只看成本列表的旧字段保留为 `binding_cost_currency`。
